# Puzzle DAG

To procedurally generate a dungeon with puzzles, we will generate a DAG.
Nodes are accomplishments like ("unlocked this door" or "obtained this key") and edges are dependencies between them.

The DAG will be built by randomly selecting from a list of "puzzle node types", such as:
* a locked door
* a key you can pick up
* a switch on the floor
* a puzzle you can solve

DAG requirements:
* Must be a single start node (or one for each player!) and a single end node (or one for each player!).
* The start node's output type must be and the end node's input type must include `access`.
* All nodes must have their input requirements satisfied by the incoming edges.

Optional features:
* Jail cell start node (see below)
* Bonus item end nodes

The dungeon is laid out by walking the DAG _backwards_: start at the dungeon exit (a node with no outgoing edges), render a room and render the exit in it, then look at the exit node's dependencies and render rooms for those (including generating rooms/hallways/tunnels etc. to connect them to the exit room) and render them in those rooms. Then repeat until you get to the source mode.

## Puzzle Node Type interface

Each component definition will have these things:

* A list of required incoming edges, with their types. For example, a locked door would require 1 edge with a type `signal_boolean` (e.g. a remote switch) or `item` (e.g. a key).
* A Boolean indicating whether presence is required to complete the puzzle
* An outgoing edge slot explaining what kind of thing can happen when the node is completed, e.g. `signal_boolean` for a switch, `item` for an item on the ground, or `access` for an unlocked door.
* A function to render the node on a physical dungeon map. Params:
    * Box on the map (room space)
    * "End" tile in that box (only guaranteed to be present if `access` is an output)
    * TODO other params?
    * Return value:
      * What to put on the map in the box.
      * Where to enter the box.
* Min size for rendering

Things we could add:
* hints? would hints be generated by nodes (whatever nodes are currently reachable but incomplete) or do they require more context than that?

## Edge types

Here are the possible edge types:

* `signal_boolean`: a remote Boolean signal. For simplicity, the destination determines whether it is one-way or repeatedly toggleable.
* `signal_multistate`: a remote multi-state toggle, like toggling between 3 or 4 different toggles. The destination determines how many states there are.
* `item`: an item that a user picks up
* `access`: physical access to a space in the dungeon
* `password`: something the user learns at the source node and uses at the destination node. TODO how to constrain this enough to be compatible? does it need to be a string?

`access` is a special type because it shapes the structure of the dungeon. Probably all nodes will require `access` as an input, but I suppose that might not always be the case.

## Examples

### Item on the ground

Simply being there is enough to complete this node.

Inputs: `access`
Output: `item`
Min size: 1x1
Render: Places the item somewhere in the given space.

### Switch

Simply being there is enough to complete this node.

Inputs: `access`
Output: `signal_boolean`
Min size: 1x1
Render: occupies the tile (it's a step switch)

### Wizard

Inputs: `access`
Outputs: `signal_boolean`
Min size: 1x2
Render: occupies the non-exit tile. Returns the exit tile as the entrance tile.

Like a Switch, but requires you to solve a riddle or something.

### Maze

Inputs: `access`
Outputs: `access`
Min size: 10x10
Render: Fills the room with a maze, with a path winding away from the exit tile and ending at the entrance tile.

Ideas:
* Could also return some internal usable boxes, e.g. a 1x1 space where an item could be inside the maze.

### Locked chest

Inputs: `access`, `signal_boolean`
Outputs: `item`
Min size: 1x2
Render: see Wizard

## Locked door

Inputs: `access`, `signal_boolean`
Outputs: `access`
Render: draws a wall across the box with exit on one side and entrance on the other. Then renders a door in the wall.
